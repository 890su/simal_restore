# Сборка и публикация SIMAL

Код нового приложения находится в `src/`, статическая сборка — `dist/`, API Cloudflare Pages — в `functions/`. Архив `site/` остаётся источником восстановления и не является папкой новой публикации.

## Локальная проверка

Требуется Node 22.12+; в CI используется Node 24. После клонирования выполнить `npm ci`, `npm test`, `npm run check`, `npm run build`. `npm run dev` запускает витрину, но не эмулирует Pages Functions/D1. Для серверной проверки использовать Wrangler Pages dev с `dist/` и локальной D1 по инструкции `quote-operations.md`.

`prebuild` выполняет импорт каталога, извлечение информационных страниц и подготовку public. Каталог берётся из `CATALOG_CSV_URL`, если переменная задана; иначе из восстановленного локального источника. Таблица должна содержать только разрешённые к публикации сведения. Токены и контакты клиентов не включать в таблицу или Git.

`scripts/prepare-public.mjs` копирует только `site/images`, `site/upload`, favicon и публичную проекцию каталога. `scripts/public-catalog.mjs` исключает отчёты восстановления, непроверенные фото-кандидаты и доказательства цен; полные описания остаются в серверной сборке HTML, а клиент получает названия, краткие описания, параметры и поля для корзины/API. Bitrix HTML, библиотеки, клиентские формы и старый runtime не копируются. Скрипт генерирует security headers и точные редиректы старых адресов, не занятых другими опубликованными страницами. Коллизии и пропущенные редиректы — `.work/public-manifest.json`.

`scripts/verify-build.mjs` проверяет готовые HTML/CSS: локальные ресурсы и ссылки, canonical, h1, отсутствие Bitrix, sitemap, hreflang на noindex и отсутствие цепочек редиректов. Отчёт — `.work/build-audit.json`; дефект останавливает сборку. Проверка не заменяет браузерный mobile QA, тест реальной заявки, Rich Results Test или полевые Core Web Vitals.

## GitHub Actions

- `Verify storefront` выполняет проверки при pull request, push в main и ручном запуске; сохраняет артефакт сборки. Он не публикует production.
- `Publish Cloudflare Pages` запускается только вручную через workflow_dispatch; по умолчанию выбирает preview. Нужны secrets `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`, при подключённой таблице — `CATALOG_CSV_URL`.
- Настроить GitHub environments `preview` и `production`; для production включить required reviewers. Сам YAML не может включить защиту environment в аккаунте.
- Перед запуском убедиться, что Pages production branch действительно `main`, проект действительно `simal` и Wrangler авторизован в нужном аккаунте. Указанные в YAML значения соответствуют локальному проекту, но не подтверждают состояние аккаунта.
- Preview собирается с `SITE_NOINDEX=true`; production — false. При прямом запуске вне workflow задавать флаг явно. Настройки доступа Pages preview и API-secrets не наследуются автоматически из GitHub.

Публикация выполняется через Wrangler Direct Upload: он обрабатывает `functions/` из корня проекта. Загрузка одной папки dist через dashboard не является проверкой API и D1. В существующем `wrangler.toml` нужно согласовать `pages_build_output_dir` с `dist` и добавить D1 binding по инструкции API. Это должно быть сделано до реального deploy.

## Серверная конфигурация и контроль выпуска

Настроить D1 binding, применить SQL migrations, добавить Telegram secrets и административный токен согласно `docs/quote-operations.md`. Отдельно проверить preview и production binding: тестовая заявка не должна попадать в рабочую базу. Прямой deploy не применяет SQL migrations автоматически.

Контроль: открыть опубликованный URL, проверить главную/категорию/товар на телефоне, сердечко и корзину после перезагрузки, отправить согласованную контрольную заявку, сверить номер и запись в D1, получить уведомление менеджера. При сбое Telegram заявка должна оставаться сохранённой и попадать в повторную доставку.

Rollback кода выполнять к конкретному проверенному deployment/commit и соответствующему снимку каталога. Откат кода не откатывает заявки и SQL-схему; миграции проектировать совместимыми и резервировать базу перед изменениями схемы. Ни workflow, ни эта инструкция не означают, что новая версия уже опубликована.
