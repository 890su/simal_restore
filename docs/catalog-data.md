# Каталог: данные, Google Таблицы и проверка импорта

Реализация 7 ноября 2026. Публикуемый снимок — `data/normalized-catalog.json`.
Исходники восстановления `data/catalog.json`, `site/data/catalog.json` и HTML в
`site/` сохраняются без изменений. Импортёр работает на Node.js без сторонних
зависимостей. Проверен на установленном Node.js.

## Команды

```powershell
# Импортировать настроенный источник: CLI > env > enabled config > архив.
node scripts/import-catalog.mjs

# Проверить источник без перезаписи рабочего снимка.
node scripts/import-catalog.mjs --check

# Автономное восстановление: принудительно игнорировать env и Google config.
node scripts/import-catalog.mjs --archive
node scripts/apply-translation-reviews.mjs

# Создать чистый CSV для загрузки в Google Таблицы.
node scripts/export-catalog-csv.mjs --output data/catalog-template.csv

# Импортировать экспорт Google Таблиц либо локальный CSV.
node scripts/import-catalog.mjs --source "https://docs.google.com/spreadsheets/d/e/PUBLISHED_ID/pub?output=csv"
node scripts/import-catalog.mjs --source data/catalog-template.csv

# В CI можно задать CATALOG_CSV_URL вместо --source.
# .env автоматически не читается: переменную передаёт среда запуска.
node --test tests/catalog.test.mjs
```

`--source` имеет приоритет над переменной `CATALOG_CSV_URL`, затем используется
`csvUrl` из включённого `catalog.config.json`, затем архив. `--archive` — явный
автономный режим, игнорирующий env/config; вместе с `--source` он не принимается.
`--check` проверяет источник и данные без записи. `--output` задаёт другой JSON
для проверки
перед публикацией. Ошибка загрузки, структуры, дубль ID, неверная цена/валюта,
небезопасный URL или отсутствующее указанное фото завершают команду с ненулевым
кодом. Существующий рабочий JSON не перезаписывается: полная проверка идёт до
записи временного файла и атомарного переименования. При ошибке выбранного
публичного CSV импорт не переключается автоматически на архив: публикация
останавливается, последний рабочий снимок сохраняется.

## Источник и подключение

Создана [рабочая Google Таблица SIMAL](https://docs.google.com/spreadsheets/d/1vLx2KoR4AR3YvzcjLLvd_Q3-5Q8RyMpqnyDAQwV4hVg/edit#gid=391044452),
лист `Products`, gid `391044452`. Репозиторий хранит её публичную конфигурацию:

```json
{
  "schemaVersion": 1,
  "enabled": false,
  "spreadsheetId": "1vLx2KoR4AR3YvzcjLLvd_Q3-5Q8RyMpqnyDAQwV4hVg",
  "gid": "391044452",
  "csvUrl": "https://docs.google.com/spreadsheets/d/1vLx2KoR4AR3YvzcjLLvd_Q3-5Q8RyMpqnyDAQwV4hVg/export?format=csv&gid=391044452"
}
```

Создание таблицы само по себе не подтверждает доступ к анонимной CSV-выдаче.
`enabled` включается только после её проверки. Фактическое
значение смотрите в `catalog.config.json`, read-back доступа — в
`docs/catalog-sheet.json`. URL конфигурации допускает только HTTPS Google Sheets
export, согласованные spreadsheetId/gid и публичные параметры format/gid.
Логины, пароли, access_token и другие секреты в конфигурацию не помещаются.
При необходимости временный явный `--source` либо `CATALOG_CSV_URL` перекрывает
config; `.env` автоматически не читается.

Старый `data/simal-catalog.csv` содержит дубли ID и не подходит как готовая
рабочая таблица. Использовать экспорт нового снимка. Каталог в таблице — полный
снимок: отсутствующие строки не попадут в новую публикацию; для временного
скрытия удобнее `active=no`.

## Контракт v1

```text
schemaVersion: 1
generatedAt: ISO timestamp
source: { type: archive|csv, files?[], location?, sha256? }
categories[]:
  id, slug, parentId|null
  translations.{ru,en,ka}: { title, url }
  legacyUrls[]
products[]:
  id: неизменяемая строка старого Bitrix ID
  sku: строка, пустая при отсутствии подтверждённого артикула
  categoryIds[]
  translations.{ru,en,ka}:
    title, description, summary, url
    attributes[]: { name, value }
  legacyUrls[]
  price: number|null
  currency: GEL
  availability: in_stock|on_order|out_of_stock|unknown
  images[]: { src, alt, sourceUrl, sourceType }
  variants[]
  active: boolean
  reviewFlags[]
  provenance[]: архивные URL/язык/название и номер строки импорта
  archivedPrices[]: исходные цены, валюты и URL для проверки
  imageCandidates[]: точные исходные URL недостающих изображений и страница-источник
report: покрытие фотографиями/переводами, отсутствующие цены, флаги проверки
```

Варианты не выведены из похожих названий. `variants` пока пуст. Английские
страницы со своими Bitrix ID не склеиваются с русскими по эвристике: для этого
нужно подтверждённое соответствие. Один ID в нескольких категориях становится
одним товаром с несколькими `categoryIds` и всеми `legacyUrls`.

Модель сохраняет старые URL, но не создаёт redirects: генератор сайта использует
их для настоящих страниц/алиасов. Если новый URL из таблицы заменяет старый,
старый остаётся в `legacyUrls`. Два разных товара не могут владеть одним URL.
Категории с доказанным путём вложения имеют `parentId`.

## Поля Google Таблицы

- Обязательны `id`, категория и хотя бы одно непустое `name_ru/name_en/name_ka`.
  Для существующего товара отсутствующие колонки сохраняют текст архива;
  явно присутствующие пустые колонки очищают соответствующие поля.
- `active`: `yes/no`, также принимаются `true/false` и `1/0`.
- `price`: число без обозначения валюты. Допустимы `1234.50`, `1234,50`,
  `1 234,50`; пустое поле означает цену по запросу, а не ноль. Запись `1,234`
  неоднозначна и отклоняется. Ноль сохраняется как число 0.
- `currency`: `GEL` (также допускается символ `₾`). Для непустой цены валюта
  обязательна. `р.`, RUB, USD и неподтверждённые конвертации отклоняются.
- `availability`: `in_stock`, `on_order`, `out_of_stock`, `unknown`; импортёр
  также понимает прежние русские/английские/грузинские обозначения.
- `category_ids`: стабильные ID категорий, несколько через ` | `. Для новой
  категории задаются ID и `category_ru/category_en/category_ka`. Названия в этих
  колонках редактируют **первую** категорию из `category_ids`; ID не меняется.
  Непустые названия одного ID/языка должны совпадать во всех строках таблицы:
  конфликт останавливает импорт. Пустые ячейки сохраняют прежнюю подпись.
  Проверенные подписи вложенных категорий, остальные языки и URL берутся из
  последнего валидного снимка и не затираются названием родительского раздела.
- `images`: существующие локальные URL файлов через ` | `, например
  `/upload/iblock/abc/chair.jpg`. Для совместимости читается и колонка `image`.
  Импорт не загружает произвольные удалённые картинки. Новый файл нужно сначала
  добавить в `site/`, подтвердив его соответствие товару; основной build копирует
  эти ресурсы в public. Пустое поле очищает галерею.
- `description_*`, `summary_*` — текст, включая переносы строк. HTML не требуется.
- `specs_*` — JSON-массив объектов `{ "name": "Ширина", "value": "80 см" }`.
  Старый формат `Ширина: 80 см | Высота: 90 см` также читается.
- `path_*` — относительные URL сайта либо полный URL simal.ge. Чужие домены,
  `javascript:`, обход каталогов и небезопасные пути отклоняются.

CSV-парсер учитывает UTF-8 BOM, CRLF, запятые/кавычки/переносы внутри полей,
удвоенные кавычки. Неверное количество колонок, повтор заголовка и незакрытая
кавычка не исправляются догадкой, а останавливают импорт.

В Google Таблицу помещаются только публичные сведения каталога. Контакты
покупателей, заявки, токены и внутренние комментарии в неё не добавляются.
Для редактирования используется рабочий Google Sheet из `catalog.config.json`;
его разрешение anyone-read предоставляется только по прямому решению владельца.

## Результат нормализации архива

- 292 архивные detail-записи → 277 уникальных ID. Дополнительно из точных HTML
  карточек листинга восстановлены 242 ID с названиями, ссылками, ценой и наличием.
  Итого **519 товаров**, 37 категорий, включая 15 вложенных.
- Сохранены 546 товарных URL и 57 URL категорий. Данные 55 восстановленных
  category HTML использованы для правильного членства товаров в подразделах,
  даже когда URL товара сам не содержит подраздел. Повтор ID не создаёт товар.
- У 242 записей `detail_page_missing`: отдельной карточки в архиве нет; описание
  и параметры не придуманы. Данные принадлежат конкретному `data-product` и
  title-link его tile, а не извлечены из похожего названия. Нераспознанных ссылок
  `data-product` в проверенных листингах не осталось.
- 24 ID с конфликтующими ценами разных архивных карточек/листингов. Их цена
  `null`, все значения сохранены в `archivedPrices`. Уже в detail-архиве цены
  конфликтовали у `9753`, `9770`, `9818`, `9820`, `10372`, `10378`.
- Всего 34 товара с `price=null`, в том числе подозрительный `13538` с валютой
  `р.`. Никакой пересчёт рублей в лари не выполняется. При противоречивом наличии
  выставлено `unknown` и флаг `availability_conflict`.
- 21 английская архивная карточка имеет отдельный ID. У 15 эвристически
  переведённых русских записей обнаружена попытка использовать URL другого
  английского товара: такие связи не перенесены, сохранён флаг проверки.
- Все архивные коммерческие данные помечены `commercial_data_unverified`:
  состояние веб-архива не подтверждает сегодняшние цену и наличие.
- Восстановленные машинные переводы помечены `translation_unverified_en/ka`.
  Отсутствующие переводы не заменяются выдуманным текстом.
- Подтверждённых локальных товарных фотографий: **1 из 519**. Список пропусков
  лежит в `report.missingImageIds`. Файл не выдаёт заглушку за фотографию.

## Проверка изображений и ограниченный поиск восстановления

Флаг `file:false` из архива игнорируется: каждый точный путь проверяется на диске.
Учитываются архивная галерея и собственные og:image/gallery в HTML карточки;
рекомендации соседних товаров и иконки категорий не присваиваются товару.
На момент проверки в `site/` 48 растровых файлов, из них 4 в `upload/iblock/`;
точных совпадений с detail-галереями не найдено. По собственному thumbnail в
category tile найдено фото ID `13527`, тумба SIRIUS 2 (сонома):
`/upload/resize_cache/iblock/2ef/250_250_1/iou4288g2qi3uts7kmojmiourf20iko6.webp`.
Источник — `https://simal.ge/catalog/tumby-dlya-obuvi/`, конкретный tile с этим
`data-product`, названием и ссылкой. Hero-файлы в `site/images/hero/`
существуют, но их происхождение и связь с конкретными товарами не подтверждены.

Временный источник прошлого восстановления найден в
`C:/Users/user/AppData/Local/Temp/simal-raw/`: `html-urls.json` содержит URL и
timestamps снимков; `home-latest.html` — сохранённую главную. Воспроизводимый
импорт от этой временной папки не зависит.

7 ноября 2026 проверены шесть точных исходных image URL на simal.ge для кровати,
дивана, матраса, стола, шкафа и тумбы. Все вернули HTTP 200, но `text/html` и
одинаковый HTML размером 58529 байт — не фотографии. Такие ответы не сохранены.
Например:

- Gannover, ID `13497`:
  `https://simal.ge/upload/iblock/1ec/55kt4y63s148imrbb7ztw4wf1w3q2ko6.webp`.
  Поиск картинок независимо вернул этот же точный исходник и карточку
  `https://simal.ge/catalog/myagkaya-mebel/divan-krovati/divan-gannover/`.
- ARIZONA, ID `9753`:
  `https://simal.ge/upload/iblock/a23/5tzms4kwk85ol155q8sa6cao4dp2hjji.jpg`.
- CARBON, ID `13708`:
  `https://simal.ge/upload/iblock/1cd/bivu8aisa3j98lpbgq8wwcbrkhjyxa0s.webp`.

Wayback availability API по этим трём точным URL вернул HTTP 429. Один прямой
playback-запрос для фото Gannover около 20 мая 2026 вернул HTTP 404. Продолжать
массовые запросы к ограниченному API не стали. Google text/image search ещё
содержит страницы и точные source URL, но исходные байты фотографии в этой
ограниченной проверке не восстановлены. Прямой Google Images HTML вернул
страницу, требующую JavaScript; изображений в ответе не было.

Следующий отдельный этап восстановления: выгрузка доступных снимков точных
image URL, сопоставление original `/upload/iblock/` и `/upload/resize_cache/`
по хешу имени, затем проверка фото поставщика по модели, размеру и цвету.
Похожее фото из выдачи не является подтверждением точного соответствия.

`data/image-recovery.json` содержит журнал ограниченных попыток и overrides
`entries`. Записей успешно скачанных фото пока нет. Формат будущей подтверждённой
записи:

```json
{
  "productId": "13497",
  "src": "/images/recovered/13497.jpg",
  "originalUrl": "https://simal.ge/upload/iblock/1ec/55kt4y63s148imrbb7ztw4wf1w3q2ko6.webp",
  "method": "google-thumbnail",
  "sourcePageUrl": "https://simal.ge/catalog/myagkaya-mebel/divan-krovati/divan-gannover/",
  "cacheUrl": "OBSERVED_ACTUAL_CACHE_URL",
  "retrievedAt": "ACTUAL_ISO_TIMESTAMP"
}
```

Пример не включён в `entries`: файла нет. Импортёр требует существующий локальный
файл, точное совпадение `originalUrl` с `product.imageCandidates` и поддержанный
метод (`google-thumbnail`, `yandex-thumbnail`, `wayback`, `original-url`). При
отсутствии доказанного совпадения импорт падает и сохраняет последний рабочий
снимок. Кэшированный thumbnail помечается `resolution=thumbnail`, исходный URL,
кэш и дата сохраняются в метаданных. Само наличие файла похожей модели не
позволяет подменить товарное фото.

Две попытки открыть инвентарь браузера через `cua.getState()` завершились
таймаутом и сбросом kernel. До открытия вкладки и обращения к пользовательским
страницам выполнение не дошло; этот путь восстановления остался непроверенным.

## Проверки

`tests/catalog.test.mjs` содержит 20 проверок: CSV с переносами и кавычками,
ошибочный CSV, числовые цены/пропуски/ноль, дедупликация с сохранением категорий
и URL, конфликт валюты, реальное наличие фото вопреки `file:false`, исключение
похожих товаров из галереи, безопасные пути, конфликт переведённых URL,
подтверждённый recovery только для exact source image (с пометкой thumbnail),
вложенные listing-категории и восстановление точных listing-only товаров,
перенос старого URL при редактировании, отказ без перезаписи рабочего снимка,
экспорт/обратный импорт Google CSV, конфликты URL и циклы категорий.

`tests/catalog-source.test.mjs` проверяет приоритет CLI/env/config, отключённый
config и архивный fallback, явный offline --archive, HTTPS и отсутствие секретов
в публичной конфигурации, явное редактирование категории, сохранение вложенных
переводов и остановку при противоречивых названиях. Реальный импорт из временной
папки проверяет загрузку категорий последнего снимка и отсутствие перезаписи при
--check/ошибке. `tests/translation-reviews.test.mjs` отдельно проверяет,
что архивные переводы не перетирают ручные правки CSV.
