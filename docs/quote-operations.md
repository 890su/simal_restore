# Заявки: хранение, уведомления и эксплуатация

Сайт принимает запрос на уточнение цены и поставки. Сохранённая цена — снимок опубликованного каталога; API не резервирует товар и не принимает оплату.

## Контракт

`POST /api/quote`, JSON, не более 32 KiB, заголовок `Origin` обязателен:

```json
{
  "requestId": "7a0ba107-6a08-46bd-9379-5a78be477159",
  "name": "Имя посетителя",
  "contact": "+995 555 123 456",
  "comment": "Пожелания к поставке",
  "lang": "ru",
  "items": [{ "id": "идентификатор-из-каталога", "quantity": 2 }],
  "website": ""
}
```

Поле `phone` допускается вместо `contact`. Контакт — телефон от семи цифр или email. Имя: 2–100 символов, контакт: до 120, комментарий: до 1500. Языки: `ru`, `en`, `ka`. В заявке от 1 до 50 разных сочетаний товара и варианта; количество — целое 1–9999. Для товара с `variants` требуется `variantId`, точно совпадающий с опубликованным вариантом. Клиентские цены, названия и наличие игнорируются; используются только опубликованные `/data/catalog.json`, `schemaVersion: 1`, `active: true`. Отсутствующая цена остаётся `null`, а не нулём. Товар с неизвестным наличием или под заказ допускается: это запрос менеджеру. Товар или выбранный вариант с `availability: "out_of_stock"` отклоняется с 409. Локализованное название сохраняется даже при отсутствии локализованного URL: ссылка берётся из RU или другой доступной канонической страницы; если валидного пути вообще нет, возвращается 503.

Клиент создаёт UUID и сохраняет его при повторе неизменённой заявки, включая повтор после сетевой ошибки. Новое содержимое получает новый UUID. Отсутствие ответа не означает, что заявка не сохранена. Порядок строк не влияет на идентичность; количества, контакт, комментарий и язык влияют.

Витрина хранит в `sessionStorage` только SHA-256 содержимого попытки и UUID. Контакт и комментарий остаются в форме и не записываются в localStorage/sessionStorage. Если после потери ответа перезагрузить страницу и заново ввести те же данные, тот же состав получит прежний UUID до закрытия вкладки. Если sessionStorage запрещён, повтор защищён в памяти текущей страницы. После подтверждения метаданные попытки удаляются. Кнопка блокируется до начала асинхронных операций; UI проверяет `accepted`, формат номера и совпадение requestId перед очисткой отправленных количеств.

Успешное первичное сохранение: HTTP 201, повтор: HTTP 200:

```json
{
  "id": "SIM-20261107-1234ABCD",
  "requestId": "7a0ba107-6a08-46bd-9379-5a78be477159",
  "status": "accepted",
  "notification": "pending",
  "duplicate": false
}
```

`accepted` означает, что заявка, все позиции и задание уведомления сохранены одним D1 batch. `pending` означает, что уведомление менеджеру ещё ожидает доставки. UI должен показать «Заявка принята» и номер; очищать только отправленный снимок товаров после этого ответа. `sent` означает подтверждение Telegram API, а не прочтение менеджером. При отсутствии Telegram-конфигурации заявка всё равно сохраняется с `pending`.

Повтор UUID с другим содержимым: `409 request_id_conflict`; неизвестный/неактивный товар: `409 product_unavailable`; ошибки полей: 400; неподходящий Origin: 403; слишком большое тело: 413; не JSON: 415; ограничение частоты: 429 с Retry-After; отсутствие D1/секрета или сбой хранения: 503. При 503 нельзя показывать подтверждение. WhatsApp может быть явным альтернативным действием посетителя, но не подтверждением доставки API.

## Настройка Cloudflare Pages

Нужны отдельные D1 базы для preview и production. Настройки не создаются этим кодом автоматически. До настройки и миграции `/api/quote` намеренно отвечает 503.

1. Создать D1 базу штатным Wrangler/панелью Cloudflare.
2. Добавить binding **QUOTES_DB** в Pages и `wrangler.toml` для нужной среды. В конфигурации указать `migrations_dir = "migrations"`. Реальный database_id берётся из созданной базы, вымышленный ID не использовать.
3. Применить `migrations/0001_quotes.sql` к выбранной базе. Для локальной проверки: `npx wrangler d1 migrations apply QUOTES_DB --local`; production требует осознанного выбора `--remote` и правильной среды.
4. Задать secrets в Cloudflare, локально — в игнорируемом `.dev.vars`. Не коммитить значения.

Для API token deployment требуются account-scoped права Pages Write (в старом UI — Cloudflare Pages Edit); создание D1 и применение миграций требуют D1 Write. Ограничить токен нужным аккаунтом. Это разные права: успешная публикация Pages не доказывает возможность создать/мигрировать D1. Права DNS для публикации кода и работы существующего binding не требуются; настройка доменов выполняется отдельно. См. [Pages API](https://developers.cloudflare.com/pages/configuration/api/) и [Create D1 Database permissions](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/create/).

| Binding / secret | Назначение |
| --- | --- |
| `QUOTES_DB` | Обязательный D1 binding. |
| `QUOTE_IP_HASH_SECRET` | Обязательный случайный секрет минимум 24 символа для HMAC IP. Для среды использовать собственный секрет. |
| `TELEGRAM_BOT_TOKEN` | Необязательный секрет доставки; без него уведомления ждут. |
| `TELEGRAM_CHAT_ID` | Получатель уведомлений, серверная переменная. |
| `QUOTE_ADMIN_TOKEN` | Отдельный случайный секрет минимум 32 символа для закрытых endpoints, не использовать токен Telegram. |
| `QUOTE_ALLOWED_ORIGINS` | Необязательный список точных origins через запятую, без пути и завершающего `/`. Текущий origin запроса и `https://simal.ge` разрешены по умолчанию. Для `https://www.simal.ge` при необходимости указать явно. |
| `TURNSTILE_SECRET_KEY` | Если задан, новый запрос требует `turnstileToken` и успешной server-side проверки. UI должен иметь публичный sitekey и widget с action `quote`. |

Catalog получает данные через `env.ASSETS.fetch`, если доступен, иначе с `/data/catalog.json` текущей публикации. Ссылки уведомления строятся под `https://simal.ge`; имя, перевод и цена берутся с сервера. Для вариантов поддерживаются `id`, `active`, необязательные `price` и `availability`.

Точные Origin-проверки ограничивают браузерные запросы; это не аутентификация. D1 атомарно ограничивает десять новых валидно сформированных попыток на HMAC IP за фиксированное десятиминутное окно. Сохранённые повторы не расходуют лимит. В production IP берётся из доверенного `CF-Connecting-IP`; без него все запросы относятся к общей группе `unknown`. Распределённый спам и DDoS требуют защиты Cloudflare/WAF, а при необходимости Turnstile. Honeypot `website` должен оставаться пустым.

## Доставка и повтор

После сохранения Pages использует `waitUntil` для первой попытки доставки, не задерживая ответ посетителю. Одно выполнение отправляет не более двух частей. Части экранируются целиком, границы не разрывают HTML entities и Unicode. Каждая часть содержит общий номер заявки и номер части.

Outbox содержит `pending/sending/sent`, прогресс `sent_parts`, число попыток, следующее время попытки и двухминутную lease. После ошибки — backoff 60 секунд с увеличением до часа. Истёкшая lease может быть подобрана заново. Успешные части не отправляются повторно при штатном восстановлении. Если Telegram принял сообщение, но сетевой ответ потерян или сохранение прогресса не удалось, повтор может создать дубль: exactly-once между D1 и Telegram не гарантируется. Номер заявки позволяет его распознать. Неопределённая доставка не уничтожает заявку.

Закрытый `POST /api/admin/retry` с `Authorization: Bearer <QUOTE_ADMIN_TOKEN>` берёт до пяти готовых outbox-заданий, каждое не более двух частей. Настроить отдельный Worker Cron Trigger или внешний защищённый scheduler, который вызывает этот endpoint каждую минуту. Pages сам по себе не запускает cron: без scheduler автоматических последующих попыток нет. Доступ к scheduler и секретам должен быть ограничен. Не передавать секрет в URL, браузерный JavaScript, репозиторий или логи. Endpoint также удаляет только устаревшие rate-limit counters; заявки и outbox не удаляет.

В репозитории подготовлен необязательный `.github/workflows/retry-quotes.yml` с интервалом десять минут. По умолчанию job пропускается и ничего не отправляет. Для включения после настройки D1 и получателя: добавить repository secrets `QUOTE_RETRY_URL` (HTTPS production URL с путём `/api/admin/retry`) и `QUOTE_RETRY_TOKEN` (значение server secret `QUOTE_ADMIN_TOKEN`), затем Actions variable `QUOTE_RETRY_ENABLED=true`. Workflow не получает доступ к коду репозитория, не выводит заявки/токены и не следует HTTP-редиректам с Authorization. Допустимые хосты: `simal.ge`, `www.simal.ge`, `simal.pages.dev`; другие требуют осознанного изменения allowlist. GitHub расписания могут задерживаться и работают на default branch; интервал не является SLA. Ручной workflow_dispatch также требует включённой переменной. Никакой запуск или настройка GitHub secrets не выполнялись при реализации.

Закрытый `GET /api/admin/quotes` с тем же Bearer возвращает последние 50 заявок и состояние доставки. Для следующей страницы передать поля возвращённого `nextCursor` как `before` и `beforeId`. Ответ содержит персональные контакты: не включать URL в публичную навигацию, не кэшировать, не проксировать без аутентификации. При отсутствии admin secret endpoints закрыты с 503; при неверном токене — 401. Это служебный API, не графическая админка.

Заявки и сообщения могут содержать персональные данные. Доступ к D1/Telegram ограничить ответственными сотрудниками; согласовать сроки хранения и резервное копирование отдельно. Данный код не выполняет автоматическую очистку заявок.

## Проверка без реальных сообщений

`node --test tests/quote.test.mjs` использует SQLite в памяти и адаптер D1. Проверяет миграцию/SQL, rollback всего batch, серверные цены, неизвестные товары и варианты, idempotency и конкурирующие повторы, частоты, Origin, размер тела, закрытые endpoints, Turnstile, отказ уведомления и возобновление по частям. Внешние HTTP-запросы заменены mocks; реальные заявки не отправляются.

Проверка не заменяет интеграционный тест в Cloudflare preview с отдельной D1 и тестовым получателем. Production end-to-end delivery не подтверждена, пока специально не выполнена одна контролируемая заявка с проверкой D1, ответа и Telegram. Код не публикует проект, не создаёт ресурсы и не меняет secrets.

Основа API: [D1 batch и транзакции](https://developers.cloudflare.com/d1/worker-api/d1-database/), [Pages bindings](https://developers.cloudflare.com/pages/functions/bindings/), [server-side Turnstile](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).
